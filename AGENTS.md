# open-mbox

A viewer for `.mbox` mail archives that runs in the browser: the file is streamed into a Web Worker, parsed and searched there, and never uploaded. Astro serves the page from Cloudflare Workers; the viewer itself is one React island. Generated from the Auditmos astro-on-cf template, without its data layer.

**The one invariant: a mailbox never leaves the browser.** Nothing in `src/mailbox/` or `src/viewer/` may send file or message contents over the network, and the content security policy in `astro.config.mjs` (`connect-src 'self'`, `img-src 'self' data:`) must stay at least that strict. Treat any new network call, upload, analytics snippet or loosened directive as a product decision to raise with the owner, not an implementation detail.

## Stack

| Layer | Technology |
|-------|-----------|
| Framework | Astro 7 (`output: "server"`) |
| Adapter | `@astrojs/cloudflare` |
| Runtime | Cloudflare Workers (`nodejs_compat`) |
| UI | React 19 island (`@astrojs/react`, `client:only`) |
| Parsing | postal-mime in a Web Worker |
| Styling | Plain CSS in `src/viewer/`, Tailwind CSS v4 entry for the shell |
| API | Astro endpoints (`src/pages/api/*.ts`) |
| Language | TypeScript (strict, `@/*` → `src/*`) |
| Linter | Biome 2 |
| Testing | Vitest |
| Dead-code | knip |
| Release | semantic-release |
| Package manager | pnpm 12 |

## Project Structure

- `src/pages/index.astro` — the only page: the layout plus `<Viewer client:only="react" />`
- `src/mailbox/` — the domain module: `createMailbox(source)` (mbox splitting on bytes, MIME parsing, search; opening a message or an attachment re-reads its byte range from `source`) and the worker protocol. `worker.ts` owns a mailbox off the main thread; `client.ts` is the UI-side handle. Tests: `src/mailbox/index.test.ts`
- `src/viewer/` — the React UI. `render.ts` holds the pure helpers, including `toSafeSrcDoc`, the policy every HTML mail body renders under
- `src/pages/` — file-based routes (`.astro`, `.md`, or `.ts` for endpoints)
- `src/pages/api/` — Astro API endpoints, one file per route or `[...slug].ts` for catch-all
- `src/pages/api/health.ts` — the exemplar endpoint: parses, delegates, responds, nothing else
- `src/health/` — the pure module beneath it, and the thing that carries the tests
- `src/pages/sitemap.xml.ts`, `src/pages/robots.txt.ts` — routes, not static files: nothing is prerendered here for a build-time sitemap to enumerate
- `src/seo/` — the module beneath them, and the source of every link-preview tag the layout emits
- `src/middleware.ts` — the one middleware: renders, then applies the header baseline. No policy of its own
- `src/security-headers/` — that baseline. Changing a header is an edit here and nowhere else; the content security policy is the exception, set as `security.csp` in `astro.config.mjs` because it needs Astro's script hashes
- `src/layouts/` — shared layouts wrapping page slots
- `src/styles/globals.css` — Tailwind v4 entry (`@import "tailwindcss";`)
- `src/env.d.ts` — declares `App.Locals` typed against Cloudflare `Env`
- `docs/` — business requirements and design docs
- `plans/` — phased implementation plans, one per PRD (created with the first one)
- `worker-configuration.d.ts` — auto-generated by `pnpm cf-typegen`, never edit
- Path alias `@/*` → `src/*`

Reusable components get a folder of their own under `src/` once a second page needs
one; there is no empty directory waiting for them. Same for domain modules — add
`src/<domain>/` when the domain appears, following `src/health/`.

## Commands

```bash
pnpm dev                  # dev server on http://localhost:3000
pnpm build                # production build to ./dist
pnpm preview              # preview the production build locally
pnpm deploy:dev           # build + wrangler deploy --env dev
pnpm deploy:staging       # build + wrangler deploy --env staging
pnpm deploy:production    # build + wrangler deploy --env production
pnpm cf-typegen           # regenerate Env types from wrangler.jsonc

pnpm test                 # vitest run
pnpm test:watch           # vitest watch
pnpm test:coverage        # vitest + v8 coverage

pnpm types                # astro check + tsc --noEmit
pnpm lint                 # biome check .
pnpm lint:fix             # biome check --write .
pnpm knip                 # unused files / deps / exports

pnpm release              # semantic-release (CI only)
```

Dependency updates come from Dependabot (`.github/dependabot.yml`), every Wednesday at 14:00 Europe/Warsaw: minor and patch grouped, each major in its own PR. There is no local update script.

## Architecture

Prefer **deep modules** (Ousterhout): small interface hiding large implementation. Test at module boundaries, not internals. See `.claude/rules/deep-modules.md`.

Technology-specific rules live in `.claude/rules/` and load in every session — `.claude/rules/frontend/astro.md`, `.claude/rules/frontend/tailwind-v4.md`, `.claude/rules/api/astro-endpoints.md`, `.claude/rules/cloudflare-deployment.md`, `.claude/rules/error-handling.md`, `.claude/rules/atomic-imports.md`, `.claude/rules/general.md`.

## Cloudflare runtime

Access bindings through `import { env } from "cloudflare:workers"` — this is the only supported pattern since Astro v6 + `@astrojs/cloudflare` v13, and still in v7 + v14 (the old `Astro.locals.runtime.env` was removed). `env` is typed against `worker-configuration.d.ts`. After editing `wrangler.jsonc` bindings, run `pnpm cf-typegen`.

`wrangler.jsonc` ships with three env blocks (`dev`, `staging`, `production`) — each gets its own Worker name. Deploy with `pnpm deploy:staging` / `pnpm deploy:production`. There is no environment-less deploy script: an unqualified deploy publishes to the top-level Worker that no `env` block owns, and `scripts/deploy-scripts.test.ts` fails if one is added back. Deploys are manual by design — CI gates the build but never ships. `.github/workflows/deploy.yml` is the button: started by hand, it runs the gates and then the matching `deploy:*` script with the `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` repository secrets.

Per-env secrets live in `.dev.vars` / `.dev.vars.staging` / `.dev.vars.production` locally (never committed) and as Cloudflare secrets in production (`wrangler secret put`). This matches the wrangler convention — `.dev.vars.<env>` is loaded ahead of `.dev.vars` when `CLOUDFLARE_ENV=<env>` is set.

<important if="you are writing or modifying tests">
- Tests live next to source as `*.test.ts`, mirrored name (`foo.ts` ↔ `foo.test.ts`)
- Vitest with globals enabled — no need to import `describe` / `it` / `expect`
- Globals are typed via `"vitest/globals"` in `tsconfig.json` (`types` array)
- Path alias `@` resolves to `src/`
- `src/pages/**` excluded from test discovery — extract endpoint logic into a `src/<domain>/` module and test that instead. `src/health/` and `src/pages/api/health.ts` are the shipped example of the split
- **Test only the module's public boundary** (exported functions), not internals — see `.claude/rules/deep-modules.md`
- **Pure functions only** in unit tests. For code that touches fs / network / process, extract a pure helper and test it; cover the side-effecting orchestrator with a separate integration test (none ship by default)
- Reference: `scripts/init-project-lib.test.ts` shows the convention — `describe` per exported function, `it.each` for parametric cases
</important>

<important if="you are creating or reviewing design documents">
- `/docs` is the single source of truth for business requirements
- Apply review notes/status updates directly in the corresponding design doc
- Never create separate md files for reviews/audits/analyses unless explicitly asked
</important>

<important if="you are editing wrangler.jsonc or adding Cloudflare bindings">
- Run `pnpm cf-typegen` immediately to keep `worker-configuration.d.ts` in sync
- Don't edit `worker-configuration.d.ts` by hand — it's auto-generated
- Prefer `custom_domain: true` over `routes` with `zone_name` (see `.claude/rules/cloudflare-deployment.md`)
</important>
